🌊 流式输出原理详解

❌ 伪流式输出

✅ 优点

  • 实现简单
  • 不依赖大模型流式支持
  • 前端控制显示速度

❌ 缺点

  • 用户等待时间长
  • 体验不够真实
  • 无法中途停止
✅ 真流式输出

✅ 优点

  • 真正的实时体验
  • 用户看到模型实时生成
  • 可以中途停止

❌ 缺点

  • 实现复杂
  • 需要全链路支持
  • 技术门槛高

🔄 真流式输出完整流程

1
用户输入问题
用户在聊天界面输入医学问题，如"我最近头痛，是什么原因？"
2
前端发送流式请求
前端调用 sendMessageStream() 方法，建立SSE连接
fetch('/api/v1/conversations/chat/stream', { method: 'POST', body: JSON.stringify({content: "我最近头痛"}) })
3
后端接收并调用RAG服务
后端API接收请求，调用RAG服务的流式生成方法
async for chunk in rag_service.generate_response_stream(): yield f"data: {json.dumps(chunk)}\n\n"
4
RAG服务调用大模型
RAG服务调用Apollo-0.5B模型，进行流式文本生成
for output in self.model.generate(inputs): new_tokens = output.sequences[0] new_text = self.tokenizer.decode(new_tokens) yield new_text
5
实时传输token
每个生成的token通过SSE协议实时传输给前端
data: {"type": "content", "content": "根据", "full_content": "根据"} data: {"type": "content", "content": "您的", "full_content": "根据您的"} data: {"type": "content", "content": "症状", "full_content": "根据您的症状"}
6
前端实时显示
前端接收每个token，实时更新聊天界面，用户看到逐字显示效果
onMessage(data) { if (data.type === 'content') { aiMessage.content = data.full_content; // 实时更新UI } }

🎯 总结

当前项目采用的是真流式输出模式，整个链路都是流式的：

  • 大模型层：Apollo-0.5B模型实时生成token
  • RAG服务层：将token流式传递给后端
  • 后端API层：使用SSE协议流式传输
  • 前端层：实时接收并显示

这种实现方式提供了真正的实时体验，用户看到的是AI模型实时生成的内容，而不是前端模拟的效果。
