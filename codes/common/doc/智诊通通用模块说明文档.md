# 智诊通通用模块说明文档

## 📋 概述

智诊通通用模块（common）为整个系统提供统一的公共功能和服务，主要包括日志管理、配置管理、工具函数等。该模块采用单例模式设计，确保在整个系统中提供一致的服务。

---

## 🏗️ 模块结构

```
codes/common/
├── __init__.py              # 模块初始化文件
├── log_config.py            # 统一日志配置系统
└── 智诊通通用模块说明文档.md    # 本文档
```

## 📝 核心功能

### 1. 统一日志管理系统

#### 功能概述

- 为所有服务提供统一的日志管理
- 支持多服务日志分离
- 自动日志轮转和文件管理
- 结构化日志记录

#### 主要特性

- **单例模式**: 确保全局唯一的日志管理器
- **多服务支持**: 为不同服务创建独立的日志文件
- **自动轮转**: 日志文件大小限制和备份管理
- **格式化输出**: 详细和简单两种日志格式
- **控制台输出**: 实时日志显示

### UnifiedLogManager (统一日志管理器)

#### 类定义

```python
class UnifiedLogManager:
    """统一日志管理器"""

    _instance = None
    _initialized = False
```

#### 主要方法

##### 1. 初始化方法

```python
def __init__(self):
    """初始化日志管理器"""
    if not self._initialized:
        self._setup_unified_logging()
        UnifiedLogManager._initialized = True
```

**功能**:

- 设置统一的日志配置
- 创建日志目录
- 配置根日志器
- 创建格式化器
- 设置控制台输出

##### 2. 服务日志设置

```python
def setup_service_logging(self, service_name: str, log_level: int = logging.INFO,
                         show_config_logs: bool = False) -> logging.Logger:
```

**参数**:

- `service_name`: 服务名称

- `show_config_logs`: 是否显示配置完成日志

**功能**:

- 为特定服务创建专用 logger
- 创建服务专用日志文件

**返回**: 配置好的 logger 实例

## 🔧 使用示例

### 1. 基础使用

#### 设置服务日志

```python
from common.log_config import setup_service_logging

# 为后端服务设置日志
logger = setup_service_logging("backend_service", show_config_logs=True)

# 记录日志
logger.info("服务启动成功")
logger.error("发生错误")
```

#### 使用便捷函数

```python
from common.log_config import get_logger

# 获取logger
logger = get_logger("backend_service")
logger.info("这是一条日志")
```

### 2. 专用日志记录

#### HTTP 请求日志

```python
from common.log_config import log_request, log_response

# 记录请求
log_request("POST", "/api/v1/conversations", user_id="user123", duration=0.5)

# 记录响应
log_response(200, {"status": "success"})
```

#### 数据库操作日志

```python
from common.log_config import log_database_operation

# 记录数据库操作
log_database_operation("INSERT", "users", record_id="user123", duration=0.1, success=True)
```

#### 用户认证日志

```python
from common.log_config import log_user_authentication

# 记录用户登录
log_user_authentication("user123", "login", success=True)
```

### 3. 使用 BackendServiceLogger 类

```python

# 获取后端服务日志记录器
backend_logger = get_backend_logger()

# 记录各种日志
backend_logger.log_request("GET", "/api/v1/health")
backend_logger.log_database_operation("SELECT", "users", success=True)
backend_logger.log_system_event("服务启动", {"version": "1.0.0"})
```

### 4. 预定义服务日志

```python

# 设置RAG服务日志

```

## 📋 最佳实践

### 1. 日志级别使用

- **DEBUG**: 详细的调试信息，生产环境通常关闭
- **INFO**: 一般信息，记录重要的业务流程
- **WARNING**: 警告信息，不影响功能但需要注意
- **ERROR**: 错误信息，需要立即处理
- **CRITICAL**: 严重错误，系统可能无法继续运行

### 2. 日志内容规范

- 使用结构化的日志数据
- 包含足够的上下文信息
- 避免记录敏感信息
- 使用有意义的日志消息

### 3. 性能考虑

- 避免在高频调用的函数中记录 DEBUG 日志
- 使用异步日志处理器
- 合理设置日志轮转参数
- 定期清理历史日志

### 4. 安全考虑

- 不记录密码等敏感信息
- 对用户输入进行脱敏处理
- 控制日志文件的访问权限
- 定期备份重要日志
