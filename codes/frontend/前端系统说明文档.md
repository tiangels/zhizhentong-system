# 智诊通 前端系统说明文档

## 📋 系统概述

智诊通前端是一个基于 Vue 3 + TypeScript + Vite 的单页应用（SPA），提供用户认证、对话问诊、对话历史、个人档案与设置等功能模块，并与后端 FastAPI 服务通过 REST/SSE 接口交互。

### 🎯 核心特性

- **现代技术栈**：Vue 3 + TypeScript + Pinia + Vue Router + Vite
- **组件库**：Ant Design Vue，自动按需导入
- **状态管理**：Pinia 管理认证状态与业务状态
- **路由守卫**：基于路由元信息处理登录/游客访问
- **API 代理**：开发环境通过 Vite 代理转发 `/api`、`/auth`、`/ws`
- **流式对话**：支持服务端事件（SSE）方式接收生成内容

---

## 🏗️ 技术栈

- **框架**：Vue 3、TypeScript

## 🔀 路由与访问控制

文件：`src/router/index.ts`

- 路由分组：`/dashboard`、`/chat`、`/profile`、`/settings` 使用 `AuthLayout.vue` 作为受保护布局
- 公开路由：`/`（首页）、`/auth/login`、`/auth/register`
- 导航守卫：
  - 设置页面标题（`meta.title`）
  - 访问受保护路由时，未登录跳转至 `/auth/login?redirect=<from>`
  - 访问游客路由时，已登录跳转 `/chat`

## 🌐 网络与接口

### 开发代理（`vite.config.ts`）

- `/api`、`/auth`、`/health` → `http://localhost:8000`
- `/ws` → `ws://localhost:8000`

### API 服务（`src/services/apiService.ts`）

- 认证：`/auth/login`、`/auth/register`、`/auth/logout`、`/auth/me`
- 对话：`/api/v1/conversations/` 列表/详情/创建/删除
- 发送消息：`POST /api/v1/conversations/{id}/messages`
- 流式消息：`POST /api/v1/conversations/{id}/messages/stream`（SSE）
- 上传：`POST /upload`（multipart/form-data）

示例：流式消息（SSE）

```ts
const url = `/api/v1/conversations/${conversationId}/messages/stream`
const response = await fetch(url, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
  body: JSON.stringify(payload),
})
const reader = response.body!.getReader()
```

## 🔐 认证与状态

- 登录后端返回：`{ user, access_token }`
- 前端将 token 包装后存入 `localStorage`（键：`USER_TOKEN`）
- 路由守卫通过 Pinia 的 `authStore.isLoggedIn` 控制访问
- `getUserInfo()` 使用 `Authorization: Bearer <token>` 访问 `/auth/me`

## ⚠️ 故障排除

### 常见问题

- 无法登录：检查后端 `/auth/login` 是否可达、跨域与代理配置
- 受保护路由跳回登录：确认 `localStorage` 中 token 是否存在与未过期
- 流式消息无内容：检查后端是否返回 `Content-Type: text/event-stream` 与 SSE 换行规范

### 调试建议

- 打开浏览器控制台网络面板，检查请求 URL、状态码、响应头
- 查看 Vite 代理日志与后端日志（`codes/backend/logs`）

### 错误代码（前端）

| 错误代码 | 描述             | 解决方案                          |
| -------- | ---------------- | --------------------------------- |
| FE001    | 未找到访问令牌   | 确认登录并检查 `localStorage`     |
| FE002    | 网络连接失败     | 确认后端运行、代理配置与端口      |
| FE003    | SSE 流式解析失败 | 检查后端 SSE 输出格式与换行       |
| FE004    | 上传失败         | 检查表单、文件大小与 Content-Type |

## 📈 最佳实践与规范

- 组件职责单一，逻辑抽离至 `services/` 与 `stores/`
- 类型完善，导出 API 类型于 `src/types/`
- 禁止在组件内直接操作 `localStorage`，统一通过工具方法
- 路由 `meta` 控制标题、权限；守卫内避免长逻辑
