# 智诊通系统服务架构说明

## 概述

智诊通系统采用微服务架构，将向量化服务和 RAG 服务分离，通过 HTTP API 进行通信。这种架构提供了更好的可扩展性、可维护性和服务独立性。

## 服务架构

```
┌─────────────────┐    HTTP API    ┌─────────────────┐
│   后端API服务    │ ──────────────► │   RAG服务       │
│   (端口8000)     │                │   (端口8002)     │
└─────────────────┘                └─────────────────┘
                                            │
                                            │ HTTP API
                                            ▼
                                   ┌─────────────────┐
                                   │   向量化服务     │
                                   │   (端口8001)     │
                                   └─────────────────┘
```

## 服务组件

### 1. 向量化服务 (Vectorization Service)

- **端口**: 8001
- **功能**: 提供文本、图像、多模态向量化服务
- **API 文档**: http://localhost:8001/docs
- **健康检查**: http://localhost:8001/health

#### 主要接口:

- `POST /api/v1/vectorize/text` - 文本向量化
- `POST /api/v1/vectorize/image` - 图像向量化
- `POST /api/v1/vectorize/multimodal` - 多模态向量化
- `GET /api/v1/models` - 获取可用模型列表
- `GET /api/v1/info` - 获取服务信息

### 2. RAG 服务 (RAG Service)

- **端口**: 8002
- **功能**: 提供检索增强生成服务
- **API 文档**: http://localhost:8002/docs
- **健康检查**: http://localhost:8002/health

#### 主要接口:

- `POST /query` - 查询接口
- `POST /stream_query` - 流式查询接口
- `GET /health` - 健康检查

### 3. 后端 API 服务 (Backend API)

- **端口**: 8000
- **功能**: 处理用户请求，调用 RAG 服务
- **职责**: 文件上传、路径传递、结果返回

## 数据流程

### 用户查询流程

1. **用户请求** → 后端 API 服务
2. **后端 API** → RAG 服务 (`POST /query`)
3. **RAG 服务** → 向量化服务 (`POST /api/v1/vectorize/text`)
4. **向量化服务** → 返回向量化结果
5. **RAG 服务** → 检索相关文档
6. **RAG 服务** → 生成回答
7. **RAG 服务** → 返回结果给后端 API
8. **后端 API** → 返回结果给用户

### 向量化流程

```
用户问题 → RAG服务 → 向量化服务API → 数据预处理 → 分词 → 向量化 → 返回向量
```

## 服务通信

### RAG 服务调用向量化服务

RAG 服务通过 HTTP 客户端调用向量化服务：

```python
# 向量化客户端
vectorization_client = VectorizationClientSync(base_url="http://localhost:8001")

# 调用向量化服务
result = vectorization_client.vectorize_text([question])
```

### 错误处理

- **连接超时**: 30 秒
- **重试机制**: 3 次重试
- **错误日志**: 详细记录所有错误信息
- **降级处理**: 向量化失败时使用本地向量化服务

## 优势

### 1. 服务解耦

- 向量化服务和 RAG 服务独立部署
- 可以单独扩展和升级
- 故障隔离

### 2. 可扩展性

- 可以部署多个向量化服务实例
- 支持负载均衡
- 支持分布式部署

### 3. 可维护性

- 服务职责清晰
- 独立开发和测试
- 版本管理简单

### 4. 性能优化

- 向量化服务可以缓存模型
- 支持批量处理
- 异步处理支持

## 故障排除

### 常见问题

1. **端口冲突**

   - 检查端口是否被占用
   - 修改配置文件中的端口设置

2. **服务连接失败**

   - 检查服务是否正常启动
   - 验证网络连接
   - 查看错误日志

3. **向量化失败**
   - 检查模型是否正确加载
   - 验证输入数据格式
   - 查看向量化服务日志
