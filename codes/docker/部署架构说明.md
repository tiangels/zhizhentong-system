# 智诊通系统部署架构说明

## 当前架构

### 混合部署模式

我们采用了**混合部署模式**，将系统分为两个部分：

#### 1. 基础设施服务（Docker 部署）

- **PostgreSQL** - 主数据库
- **Redis** - 缓存服务
- **Elasticsearch** - 搜索引擎
- **Kibana** - ES 可视化界面
- **RabbitMQ** - 消息队列
- **ChromaDB** - 向量数据库

#### 2. 应用服务（本地部署）

- **向量化服务** - 多模态向量化处理
- **RAG 检索服务** - 知识检索服务
- **后端 API 服务** - 业务逻辑处理
- **前端服务** - 用户界面

## 启动方式

### 一键启动（推荐）

```bash
cd codes
./start-local.sh
```

### 分步启动

```bash
# 1. 启动基础设施服务
cd codes/docker
docker compose -f docker-compose.infrastructure.yml up -d

# 2. 启动应用服务
cd codes
./start-local.sh
```

### 停止服务

```bash
cd codes
./stop-local.sh
```

### Docker 配置文件

- `docker-compose.infrastructure.yml` - 基础设施服务配置

## 日志管理

### 日志文件位置

- `logs/backend_service.log` - 后端服务日志
- `logs/embedding_service.log` - 向量化服务日志
- `logs/rag_service.log` - RAG 检索服务日志

```bash
# 查看所有日志
tail -f logs/*.log

# 查看特定服务日志
tail -f logs/backend_service.log
```

## 故障排除

### 常见问题

1. **端口冲突**

   - 使用 `lsof -i :端口号` 查看端口占用
   - 修改配置文件中的端口号
   - 停止占用端口的其他服务

2. **服务启动失败**

   - 检查依赖服务是否正常运行
   - 查看服务日志文件
   - 验证环境变量配置

3. **数据库连接失败**

   - 确保 PostgreSQL 容器正在运行
   - 检查数据库连接字符串
   - 等待数据库完全启动

4. **模型下载失败**
   - 检查网络连接
   - 设置代理（如果需要）
   - 手动下载模型到缓存目录

## 生产环境建议

### 容器化部署

对于生产环境，建议将所有服务容器化：

1. **使用完整的 Docker Compose 配置**
2. **配置负载均衡和反向代理**
3. **设置监控和告警**
4. **使用容器编排工具（如 Kubernetes）**
5. **配置 SSL 证书和 HTTPS**

### 性能优化

1. **使用多阶段构建优化镜像大小**
2. **配置资源限制和健康检查**
3. **使用持久化存储**
4. **配置日志轮转和清理**

## 开发工作流

### 日常开发

1. 启动基础设施服务：`docker compose -f docker-compose.infrastructure.yml up -d`
2. 启动应用服务：`./start-local.sh`
3. 进行开发和调试
4. 停止服务：`./stop-local.sh`

### 代码修改

- 后端服务支持热重载，修改代码后自动重启
- 前端服务支持热重载，修改代码后自动刷新
- 向量化和 RAG 服务需要手动重启

### 调试技巧

- 使用 `tail -f logs/*.log` 监控服务日志
- 使用 `docker logs 容器名` 查看 Docker 服务日志
- 使用 `ps aux | grep 服务名` 查看进程状态
- 使用 `netstat -tlnp` 查看端口占用情况
